Can LLMs Beat Classical Hyperparameter Optimization Algorithms? A Study on AutoResearch

An unusual paper on HPO and the integration of LLMs within it, where HPO stands for Hyperparameter Optimization.

There is a widespread belief that LLMs can reason their way through complex search spaces by scanning experiment histories. This paper examines whether prompting an agent to write training code or suggest hyperparameters actually works for configuring learning processes. The tension here lies between the raw domain knowledge of language models and the formal trajectory tracking of classical algorithms.

The core object constructed is a hybrid optimization procedure called Centaur. It optimizes the hyperparameters of a small decoder-only Transformer model trained on web text. The input is a search space of fourteen variables automatically extracted from the abstract syntax tree of a training script. The output is a selected configuration, using validation bits-per-byte as the formal evaluation signal.

The experimental design examines three paradigms under a given, time-constrained hardware budget. First, classical hyperparameter optimization methods search within a fixed space. Second, agents driven purely by LLMs search within that same fixed space or directly and iteratively rewrite the training source code. Third, the authors introduce Centaur, a hybrid system coupling a language model with a Covariance Matrix Adaptation Evolution Strategy. This strategy is a derivative-free optimizer that models the search space as a multivariate Gaussian distribution, iteratively updating the mean vector, step size, and covariance matrix based on evaluated samples.

In Centaur, the classical optimizer acts as the primary search engine, proposing hyperparameter candidates in each trial. However, with a predetermined probability, the system delegates candidate generation to the LLM. The LLM receives a text prompt containing the optimizer's explicit internal state—specifically the mean, step size, and covariance matrix—alongside a list of the top five previous hyperparameter configurations (or "configs," I presume) and a history of recent trials. The LLM then generates a new configuration (which typically overrides the classical proposal, according to the paper). Regardless of whether the classical algorithm or the LLM generated the candidate, it is fed back into the classical optimizer to update its internal distribution. To evaluate memory awareness, the authors assign a heavy penalty to configurations that cause out-of-memory errors, forcing the optimizers to learn "safe boundaries."

Previous integrations of LLMs into optimization processes typically utilized them as surrogate models within a Bayesian optimization framework, as seen in methods like LLAMBO. Algorithms unrelated to LLMs partition the search space spatially and restrict the LLMs to specific sub-regions. The shift introduced by Centaur is the incorporation of the classical optimizer’s internal distribution state directly into the prompt. Instead of letting the LLM implicitly learn the characteristics of the search space purely from previous losses, Centaur provides a processed summary of where the best configurations cluster and how they correlate. Covariance Matrix Adaptation was specifically chosen for this hybrid approach because its state variables naturally translate into natural language descriptions.

The approach relies heavily on the assumption that the language model can effectively analyze and utilize raw statistical moments provided via text. A primary failure mode of LLM-based optimizers identified in the methodology is their struggle to track the optimization state across long experiment histories, often causing them to repeat configurations that crash the hardware. While the hybrid method delegates state tracking to the classical algorithm, the language model still lacks direct awareness of hardware constraints unless explicitly penalized through the objective function. Furthermore, extracting hyperparameters through abstract syntax tree parsing requires predefined ranges rooted in human domain knowledge, meaning the search space is not entirely free from manual filtering and curation.

The computational complexity of these approaches shifts the inference overhead directly into the optimization loop. Using larger models effectively creates a bottleneck in the search process by increasing the time required to generate proposals between training runs. Deploying unconstrained code generation necessitates higher-capacity models simply to synthesize syntactically valid training scripts.

Despite all the drawbacks, the idea is quite interesting…
