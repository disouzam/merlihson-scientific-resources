Who Wins at Scale: N-gram Embedding Scaling or Scaling the Number of Experts in LLMs

Mike’s Daily Paper Review: 06.02.26, Review 574Scaling Embedding Outperforms Scaling Experts in Language Models

The dominance of the Mixture-of-Experts (MoE) architecture for scaling LLMs is hitting an efficiency wall. While MoE decouples the total number of parameters from the compute volume, it generates significant communication overhead and memory bandwidth bottlenecks in GPU memory. This paper proposes a new structural axis: scaling the embedding layer as a dimension for increasing model parameters. As we "embed" more token combinations (a larger dictionary/embedding table), the number of model parameters increases, but the amount of computation remains roughly the same as in MoE.

The central innovation is the N-gram Embedding layer (NE), which is structured like a multi-layer hash table. In standard Transformers, a token t is mapped to a single vector in the E_0 dictionary, which the authors call the Base Embedding Table. The proposed architecture extends this by summing the base vector with embeddings from sub-tables of different n-grams that the token is part of, for various n values. For a given token, the model performs a lookup not only for the individual token but also for its context up to depth N. All of this is done without an explicit dic meaning there is no direct mapping between tokens and their embeddings as in standard Transformers.

To manage the combinatorial explosion of potential N-grams without an explicit dictionary, the authors use a Polynomial Rolling Hash function. it maps an N-gram to an index in a fixed-size expanded embedding table. To further refine the representational power and minimize the impact of hash collisions (where different N-grams map to the same vector), the architecture decomposes each N-gram into k independent sub-tables. Each sub-table uses a different hash mapping, followed by a linear transformation to map the sub-vectors back to a vector in the model's internal embedding dimension. The dimensions of these sub-tables are kept inversely proportional to the number of sub-tables, ensuring that the number of parameters remains constant for any choice of N and k.

The paper identifies three fundamental architectural principles for successful embedding scaling. First, there is a "sweet spot" for integration: NE should only be introduced when the model's MoE reaches high sparsity levels (many experts), as Expert Scaling is more efficient in low-parameter regimes. Second, the authors define a parameter budget limit, suggesting that NE should not constitute more than 50% of the total model parameters to prevent a decline in performance relative to standard MoE. Third, they identify a non-linear correlation between hash collisions and the dictionary; collisions spike when the N-gram table size is an integer multiple of the base dictionary size. Therefore, the size of the expanded table must be "offset" from these multiples.

A significant technical obstacle that must be addressed with NE is "signal weakening." In deep models, the L2 norm of the attention mechanism output can be an order of magnitude larger than the identity branch (recall the ResNet structure there) that carries the embedding signal. To prevent the loss of embedding information, the authors use "Embedding Amplification." This involves multiplying the embedding output by the square root of the model's hidden dimension or applying LayerNorm before the Residual connection to ensure the embedding contributes significantly throughout training and is learned properly.

During inference, the authors reduce the I/O cost of the large embedding tables using an N-gram Cache. This mechanism, managed via custom CUDA kernels directly on the machine, mimics the logic of a KV-cache to eliminate redundant N-gram lookups and synchronizes with a Speculative Decoding mechanism. By shifting parameters from MoE layers (which require complex routing) to the embedding layer (which uses O(1) lookups), the model reduces the number of activated parameters in FFNs, significantly easing the memory I/O bottleneck during generation.
